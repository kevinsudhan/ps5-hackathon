# Queries the product depends on

Generated by `python -m scripts.export_queries` from `backend/promisegraph/falkor_store.py` and `memory.py` (FalkorDB, the product) and `pg_store.py` (Postgres, benchmark baseline only). Do not edit by hand.

## Q1. Cascade: which promises does a disruption break?

Finds legs at a closed hub inside the closure window, walks `FEEDS` up to `depth` hops, shrinks the delay by each edge's `buffer_days`, keeps the worst delay per shipment, and returns the active promises that now land late, with days late and penalty. Used by the Impact Analyst, Finance, Verifier and the UI.

```cypher
MATCH (e:Event {id: $event})-[:AFFECTS]->(h:Hub)
WITH e, [(h)<-[:TO]-(l:Leg) WHERE l.arrive_day >= e.start_day AND l.arrive_day <= e.end_day | [l, l.arrive_day]]
      + [(h)<-[:FROM]-(l:Leg) WHERE l.depart_day >= e.start_day AND l.depart_day <= e.end_day | [l, l.depart_day]]
      AS touches
UNWIND touches AS touch
WITH e, touch[0] AS l, touch[1] AS t
MATCH (l)<-[:USES]-(s0:Shipment)
WITH ID(s0) AS sid, max(e.end_day + e.backlog_days - t + 1) AS d0
MATCH (s0) WHERE ID(s0) = sid
MATCH p = (s0)-[:FEEDS*0..8]->(s:Shipment)
WITH s, length(p) AS hops,
     reduce(d = d0, f IN relationships(p) |
            CASE WHEN d > f.buffer_days THEN d - f.buffer_days ELSE 0 END) AS delay
WHERE delay > 0
WITH s, max(delay) AS delay, min(hops) AS hops

MATCH (s)<-[:FULFILLED_BY]-(o:Order)-[:HAS_PROMISE]->(pr:Promise {status: 'active'})
WITH pr, o, s, delay, hops, s.eta_day + delay - pr.due_day AS days_late
WHERE days_late > 0
RETURN pr.id, o.id, s.id, delay, hops, days_late, days_late * pr.penalty_per_day
```

Postgres baseline, recursive CTE (same answer, checked by the benchmark):

```sql
WITH RECURSIVE
hit AS (
    SELECT x.shipment_id AS sid, MAX(e.end_day + e.backlog_days - x.t + 1) AS d0
    FROM event e
    JOIN affects a ON a.event_id = e.id
    CROSS JOIN LATERAL (
        SELECT l.shipment_id, l.arrive_day AS t FROM leg l
        WHERE l.to_hub = a.hub_id AND l.arrive_day BETWEEN e.start_day AND e.end_day
        UNION ALL
        SELECT l.shipment_id, l.depart_day FROM leg l
        WHERE l.from_hub = a.hub_id AND l.depart_day BETWEEN e.start_day AND e.end_day
    ) x
    WHERE e.id = %(event)s
    GROUP BY x.shipment_id
),
cascade (sid, delay, hops) AS (
    SELECT sid, d0, 0 FROM hit
    UNION
    SELECT f.dst, c.delay - f.buffer_days, c.hops + 1
    FROM cascade c
    JOIN feeds f ON f.src = c.sid
    WHERE c.hops < %(depth)s AND c.delay - f.buffer_days > 0
),
worst AS (
    SELECT sid, MAX(delay) AS delay, MIN(hops) AS hops FROM cascade GROUP BY sid
)
SELECT p.id, o.id, w.sid, w.delay, w.hops,
       s.eta_day + w.delay - p.due_day AS days_late,
       (s.eta_day + w.delay - p.due_day) * p.penalty_per_day AS penalty
FROM worst w
JOIN shipment s ON s.id = w.sid
JOIN fulfilled_by fb ON fb.shipment_id = w.sid
JOIN orders o ON o.id = fb.order_id
JOIN promise p ON p.order_id = o.id
WHERE p.status = 'active' AND s.eta_day + w.delay > p.due_day
```

## Q1b. What-if cascade: the same, after a rescue

Q1 with some directly hit shipments given a new starting delay (the residual delay after a reroute). Finance prices every plan with it and the Verifier re-checks it, so savings are computed by Cypher.

```cypher
MATCH (e:Event {id: $event})-[:AFFECTS]->(h:Hub)
WITH e, [(h)<-[:TO]-(l:Leg) WHERE l.arrive_day >= e.start_day AND l.arrive_day <= e.end_day | [l, l.arrive_day]]
      + [(h)<-[:FROM]-(l:Leg) WHERE l.depart_day >= e.start_day AND l.depart_day <= e.end_day | [l, l.depart_day]]
      AS touches
UNWIND touches AS touch
WITH e, touch[0] AS l, touch[1] AS t
MATCH (l)<-[:USES]-(s0:Shipment)
WITH ID(s0) AS sid, max(e.end_day + e.backlog_days - t + 1) AS d0
MATCH (s0) WHERE ID(s0) = sid
WITH s0, coalesce(head([i IN range(0, size($ov_ids) - 1) WHERE $ov_ids[i] = s0.id | $ov_delays[i]]), d0) AS d0
MATCH p = (s0)-[:FEEDS*0..8]->(s:Shipment)
WITH s, length(p) AS hops,
     reduce(d = d0, f IN relationships(p) |
            CASE WHEN d > f.buffer_days THEN d - f.buffer_days ELSE 0 END) AS delay
WHERE delay > 0

MATCH (s)<-[:FULFILLED_BY]-(o:Order)-[:HAS_PROMISE]->(pr:Promise {status: 'active'})
WITH pr, o, s, delay, hops, s.eta_day + delay - pr.due_day AS days_late
WHERE days_late > 0
RETURN pr.id, o.id, s.id, delay, hops, days_late, days_late * pr.penalty_per_day
```

## Q3. Stranded clusters (Weakly Connected Components)

Tags impacted shipments `:Impacted`, then `algo.WCC` over `FEEDS` splits them into independent problems. Each cluster lists its root shipments (hops = 0): rescue those, save the cluster.

```cypher
UNWIND $rows AS r
MATCH (s:Shipment {id: r[0]})
SET s:Impacted, s.impact_delay = r[1], s.impact_hops = r[2]

// then
CALL algo.WCC({nodeLabels: ['Impacted'], relationshipTypes: ['FEEDS']}) YIELD node, componentId
OPTIONAL MATCH (node)<-[:FULFILLED_BY]-(o:Order)
OPTIONAL MATCH (o)-[:HAS_PROMISE]->(pr:Promise)
WITH componentId, node,
     CASE WHEN pr.status = 'active' AND node.eta_day + node.impact_delay > pr.due_day
          THEN (node.eta_day + node.impact_delay - pr.due_day) * pr.penalty_per_day END AS penalty
RETURN componentId,
       count(node) AS shipments,
       collect(CASE WHEN node.impact_hops = 0 THEN node.id END) AS roots,
       count(penalty) AS promises_at_risk,
       sum(penalty) AS penalty_usd
ORDER BY penalty_usd DESC
```

```sql
    WHERE e.id = %(event)s

),
cascade (sid, delay, hops) AS (
    SELECT sid, d0, 0 FROM hit
    UNION
    SELECT f.dst, c.delay - f.buffer_days, c.hops + 1
    FROM cascade c
    JOIN feeds f ON f.src = c.sid
    WHERE c.hops < %(depth)s AND c.delay - f.buffer_days > 0
),
worst AS (
    SELECT sid, MAX(delay) AS delay, MIN(hops) AS hops FROM cascade GROUP BY sid
),
imp AS (SELECT w.sid, w.delay, w.hops, s.eta_day FROM worst w JOIN shipment s ON s.id = w.sid),
edge AS (
    SELECT f.src AS a, f.dst AS b FROM feeds f
    JOIN imp x ON x.sid = f.src JOIN imp y ON y.sid = f.dst
),
undirected AS (SELECT a, b FROM edge UNION ALL SELECT b, a FROM edge),
reach (root, node) AS (
    SELECT sid, sid FROM imp
    UNION
    SELECT r.root, u.b FROM reach r JOIN undirected u ON u.a = r.node
),
comp AS (SELECT node AS sid, MIN(root) AS cluster FROM reach GROUP BY node),
late AS (
    SELECT i.sid, (i.eta_day + i.delay - p.due_day) * p.penalty_per_day AS penalty
    FROM imp i
    JOIN fulfilled_by fb ON fb.shipment_id = i.sid
    JOIN promise p ON p.order_id = fb.order_id
    WHERE p.status = 'active' AND i.eta_day + i.delay > p.due_day
)
SELECT c.cluster,
       COUNT(DISTINCT c.sid) AS shipments,
       ARRAY_AGG(DISTINCT c.sid) FILTER (WHERE i.hops = 0) AS roots,
       COUNT(l.penalty) AS promises_at_risk,
       SUM(l.penalty) AS penalty_usd,
       ARRAY_AGG(DISTINCT c.sid) AS members
FROM comp c
JOIN imp i ON i.sid = c.sid
LEFT JOIN late l ON l.sid = c.sid
GROUP BY c.cluster
ORDER BY penalty_usd DESC NULLS LAST
```

## Q4. Chokepoints (betweenness centrality)

Which hubs do the most shortest routes depend on? The Sentinel uses the rank of the closed hub.

```cypher
CALL algo.betweenness({nodeLabels: ['Hub'], relationshipTypes: ['LANE'], samplingSize: 100000}) YIELD node, score
RETURN node.id, node.name, node.kind, score ORDER BY score DESC LIMIT $k
```

Postgres baseline, pgRouting (same answer, checked by the benchmark):

```sql
WITH
v AS (SELECT id, name, kind, ROW_NUMBER() OVER (ORDER BY id) AS vid FROM hub),
e AS (
    SELECT ROW_NUMBER() OVER (ORDER BY l.src, l.dst, l.mode) AS id, a.vid AS source, b.vid AS target,
           l.mode, l.days, l.cost_per_kg
    FROM lane l JOIN v a ON a.id = l.src JOIN v b ON b.id = l.dst
),
n AS (SELECT count(*) AS n FROM (SELECT source FROM e UNION SELECT target FROM e) x),
bc AS (
    SELECT vid, centrality FROM pgr_betweennessCentrality((
        SELECT 'SELECT id, source, target, 1::float8 AS cost FROM unnest('
               || quote_literal(array_agg(id)) || '::bigint[], '
               || quote_literal(array_agg(source)) || '::bigint[], '
               || quote_literal(array_agg(target)) || '::bigint[]) AS e(id, source, target)'
        FROM e), directed => true)
)
SELECT v.id, v.name, v.kind, bc.centrality * (n.n - 1) * (n.n - 2) AS score
FROM bc JOIN v ON v.vid = bc.vid CROSS JOIN n
ORDER BY score DESC LIMIT %(k)s
```

## Q5. Reroutes (k shortest weighted paths)

`algo.SPpaths` over `LANE` edges, weighted by `days` (fastest) or `cost_per_kg` (cheapest), dropping any path through a closed hub. The Rerouter runs it for every cluster root.

```cypher
MATCH (a:Hub {id: $src}), (b:Hub {id: $dst})
CALL algo.SPpaths({sourceNode: a, targetNode: b, relTypes: ['LANE'], weightProp: 'days',
                   costProp: 'cost_per_kg', pathCount: 20, maxLen: 7})
YIELD path, pathWeight, pathCost
WITH path, pathWeight, pathCost WHERE none(n IN nodes(path) WHERE n.id IN $closed)
RETURN [n IN nodes(path) | n.id] AS hubs, [r IN relationships(path) | r.mode] AS modes,
       pathWeight, pathCost
ORDER BY pathWeight LIMIT $k
```

Postgres baseline, pgRouting (same answer, checked by the benchmark):

```sql
WITH
v AS (SELECT id, name, kind, ROW_NUMBER() OVER (ORDER BY id) AS vid FROM hub),
e AS (
    SELECT ROW_NUMBER() OVER (ORDER BY l.src, l.dst, l.mode) AS id, a.vid AS source, b.vid AS target,
           l.mode, l.days, l.cost_per_kg
    FROM lane l JOIN v a ON a.id = l.src JOIN v b ON b.id = l.dst
),
ksp AS (
    SELECT k.path_id, k.path_seq, k.node, k.edge FROM pgr_KSP(
        (SELECT 'SELECT * FROM unnest('
                || quote_literal(array_agg(id)) || '::bigint[], '
                || quote_literal(array_agg(source)) || '::bigint[], '
                || quote_literal(array_agg(target)) || '::bigint[], '
                || quote_literal(array_agg({weight}::float8)) || '::float8[]) AS e(id, source, target, cost)'
         FROM e),
        (SELECT vid FROM v WHERE id = %(src)s), (SELECT vid FROM v WHERE id = %(dst)s), %(K)s, directed => true) k
),
path AS (
    SELECT k.path_id, array_agg(v.id ORDER BY k.path_seq) AS hubs,
           array_agg(e.mode ORDER BY k.path_seq) FILTER (WHERE e.id IS NOT NULL) AS modes,
           sum(e.days) AS days, sum(e.cost_per_kg) AS usd, sum(e.{weight}) AS weight, count(e.id) AS lanes,
           bool_or(v.id = ANY(%(closed)s::text[])) AS through_closed
    FROM ksp k JOIN v ON v.vid = k.node LEFT JOIN e ON e.id = k.edge
    GROUP BY k.path_id
),
short AS (SELECT * FROM path WHERE lanes <= %(max_len)s ORDER BY weight, path_id LIMIT %(paths)s)
SELECT (SELECT count(*) FROM path) AS found, (SELECT count(*) FROM short) AS kept,
       r.hubs, r.modes, r.days, r.usd
FROM (SELECT 1) one
LEFT JOIN LATERAL (SELECT * FROM short WHERE NOT through_closed ORDER BY weight, path_id LIMIT %(k)s) r ON true
```

## Q6. Direct hits

Which leg of which shipment touches a closed hub in the window, where the goods come from and where the shipment must end up. The Sentinel counts them; the Rerouter starts reroutes from them.

```cypher
MATCH (e:Event {id: $event})-[:AFFECTS]->(h:Hub)
WITH e, h, [(h)<-[:TO]-(l:Leg) WHERE l.arrive_day >= e.start_day AND l.arrive_day <= e.end_day
            | [l, l.arrive_day, 'TO']]
         + [(h)<-[:FROM]-(l:Leg) WHERE l.depart_day >= e.start_day AND l.depart_day <= e.end_day
            | [l, l.depart_day, 'FROM']] AS touches
UNWIND touches AS touch
WITH e, h, touch[0] AS l, touch[1] AS t, touch[2] AS direction
MATCH (l)<-[:USES]-(s:Shipment), (l)-[:FROM]->(a:Hub)
MATCH (s)-[:USES]->(last:Leg)-[:TO]->(dest:Hub)
WITH e, h, l, t, direction, s, a, last, dest ORDER BY last.seq DESC
WITH e, h, l, t, direction, s, a, collect(dest)[0] AS dest
RETURN s.id, s.stage, s.weight_kg, s.eta_day, h.id, l.id, l.seq, direction, t, l.depart_day, a.id, dest.id,
       e.end_day + e.backlog_days - t + 1 AS d0
ORDER BY s.id, l.seq
```

## P1. Prompt box: orders at risk (optionally one city)

Template `at_risk`. Like Q1, plus the shipment at the start of each order's worst delay path. The engine switch runs either version; tests/test_questions.py checks they return the same rows.

```cypher
MATCH (e:Event {id: $event})-[:AFFECTS]->(h:Hub)
WITH e, h, [(h)<-[:TO]-(l:Leg) WHERE l.arrive_day >= e.start_day AND l.arrive_day <= e.end_day | [l, l.arrive_day]]
         + [(h)<-[:FROM]-(l:Leg) WHERE l.depart_day >= e.start_day AND l.depart_day <= e.end_day | [l, l.depart_day]]
         AS touches
UNWIND touches AS touch
WITH e, h, touch[0] AS l, touch[1] AS t
MATCH (l)<-[:USES]-(s0:Shipment)
WITH ID(s0) AS sid, max(e.end_day + e.backlog_days - t + 1) AS d0, min(h.id) AS port
MATCH (s0) WHERE ID(s0) = sid
MATCH p = (s0)-[:FEEDS*0..8]->(s:Shipment)
WITH s, s0, port, length(p) AS hops,
     reduce(d = d0, f IN relationships(p) | CASE WHEN d > f.buffer_days THEN d - f.buffer_days ELSE 0 END) AS delay
WHERE delay > 0
WITH s, s0, port, hops, delay ORDER BY delay DESC, hops ASC, s0.id ASC
WITH s, max(delay) AS delay, min(hops) AS steps, collect([s0.id, port, s0.description])[0] AS root
MATCH (s)<-[:FULFILLED_BY]-(o:Order)-[:HAS_PROMISE]->(pr:Promise {status: 'active'})
WITH pr, o, s, delay, steps, root, s.eta_day + delay - pr.due_day AS late
WHERE late > 0
MATCH (c:Customer)-[:PLACED]->(o)
WITH pr, o, c, late, steps, root WHERE $city IS NULL OR c.city = $city
RETURN pr.id, o.id, c.name, c.city, pr.due_date, late, late * pr.penalty_per_day, steps, root[0], root[2], root[1]
```

Postgres baseline, prompt-box twin (same answer, checked by the benchmark):

```sql
WITH RECURSIVE
hit AS (
    SELECT x.shipment_id AS sid, MAX(e.end_day + e.backlog_days - x.t + 1) AS d0, MIN(x.hub) AS port
    FROM event e
    JOIN affects a ON a.event_id = e.id
    CROSS JOIN LATERAL (
        SELECT l.shipment_id, l.arrive_day AS t, a.hub_id AS hub FROM leg l
        WHERE l.to_hub = a.hub_id AND l.arrive_day BETWEEN e.start_day AND e.end_day
        UNION ALL
        SELECT l.shipment_id, l.depart_day, a.hub_id FROM leg l
        WHERE l.from_hub = a.hub_id AND l.depart_day BETWEEN e.start_day AND e.end_day
    ) x
    WHERE e.id = %(event)s
    GROUP BY x.shipment_id
),
walk (root, port, sid, delay, hops) AS (
    SELECT sid, port, sid, d0, 0 FROM hit
    UNION
    SELECT w.root, w.port, f.dst, w.delay - f.buffer_days, w.hops + 1
    FROM walk w JOIN feeds f ON f.src = w.sid
    WHERE w.hops < %(depth)s AND w.delay - f.buffer_days > 0
),
worst AS (SELECT sid, MAX(delay) AS delay, MIN(hops) AS steps FROM walk GROUP BY sid),
best AS (
    SELECT DISTINCT ON (sid) sid, root, port FROM walk
    ORDER BY sid, delay DESC, hops ASC, root COLLATE "C" ASC
)
SELECT p.id, o.id, c.name, c.city, p.due_date,
       s.eta_day + w.delay - p.due_day AS late,
       (s.eta_day + w.delay - p.due_day) * p.penalty_per_day AS fee,
       w.steps, b.root, rs.description, b.port
FROM worst w
JOIN best b ON b.sid = w.sid
JOIN shipment s ON s.id = w.sid
JOIN fulfilled_by fb ON fb.shipment_id = w.sid
JOIN orders o ON o.id = fb.order_id
JOIN promise p ON p.order_id = o.id
JOIN customer c ON c.id = o.customer_id
JOIN shipment rs ON rs.id = b.root
WHERE p.status = 'active' AND s.eta_day + w.delay > p.due_day
  AND (%(city)s::text IS NULL OR c.city = %(city)s::text)
```

## P3. Prompt box: why one customer's order is late

Template `why_late`: the worst delay path from the closed port to that customer's parcel, step by step.

```cypher
MATCH (e:Event {id: $event})-[:AFFECTS]->(h:Hub)
WITH e, h, [(h)<-[:TO]-(l:Leg) WHERE l.arrive_day >= e.start_day AND l.arrive_day <= e.end_day | [l, l.arrive_day]]
         + [(h)<-[:FROM]-(l:Leg) WHERE l.depart_day >= e.start_day AND l.depart_day <= e.end_day | [l, l.depart_day]]
         AS touches
UNWIND touches AS touch
WITH e, h, touch[0] AS l, touch[1] AS t
MATCH (l)<-[:USES]-(s0:Shipment)
WITH ID(s0) AS sid, max(e.end_day + e.backlog_days - t + 1) AS d0, min(h.id) AS port
MATCH (s0) WHERE ID(s0) = sid
MATCH p = (s0)-[:FEEDS*0..8]->(s:Shipment)
// Walk OUT from s and filter the customer by name. Matching from the indexed customer INTO s
// (bound by the variable-length path) returns 0 rows on this FalkorDB build: engine bug #8.
// The WITH barrier is needed too: without it the planner fuses the clauses and returns nothing.
WITH p, port, d0, s
MATCH (s)<-[:FULFILLED_BY]-(o:Order)<-[:PLACED]-(c:Customer)
WHERE c.name = $customer
MATCH (o)-[:HAS_PROMISE]->(pr:Promise {status: 'active'})
WITH p, port, d0, s, pr, c,
     reduce(d = d0, f IN relationships(p) | CASE WHEN d > f.buffer_days THEN d - f.buffer_days ELSE 0 END) AS delay
WHERE delay > 0 AND s.eta_day + delay > pr.due_day
WITH p, port, d0, pr, c, delay, s.eta_day + delay - pr.due_day AS late,
     reduce(k = '', n IN nodes(p) | k + n.id + '>') AS pathkey
ORDER BY late DESC, pr.id ASC, delay DESC, length(p) ASC, pathkey ASC
LIMIT 1
WITH p, port, pr, c, late, [f IN relationships(p) | f.buffer_days] AS bufs,
     reduce(acc = [d0], f IN relationships(p) |
            acc + [CASE WHEN acc[size(acc) - 1] > f.buffer_days THEN acc[size(acc) - 1] - f.buffer_days ELSE 0 END]) AS delays
UNWIND range(0, length(p)) AS i
WITH i, nodes(p)[i] AS n, port, pr, c, late, bufs, delays
RETURN i, n.id, n.description, [(n)-[:USES]->(lg:Leg {seq: 1})-[:FROM]->(fh:Hub) | fh.name][0],
       delays[i], CASE WHEN i = 0 THEN NULL ELSE bufs[i - 1] END,
       pr.id, c.city, pr.due_date, late, late * pr.penalty_per_day, port
ORDER BY i
```

Postgres baseline, prompt-box twin (same answer, checked by the benchmark):

```sql
WITH RECURSIVE
hit AS (
    SELECT x.shipment_id AS sid, MAX(e.end_day + e.backlog_days - x.t + 1) AS d0, MIN(x.hub) AS port
    FROM event e
    JOIN affects a ON a.event_id = e.id
    CROSS JOIN LATERAL (
        SELECT l.shipment_id, l.arrive_day AS t, a.hub_id AS hub FROM leg l
        WHERE l.to_hub = a.hub_id AND l.arrive_day BETWEEN e.start_day AND e.end_day
        UNION ALL
        SELECT l.shipment_id, l.depart_day, a.hub_id FROM leg l
        WHERE l.from_hub = a.hub_id AND l.depart_day BETWEEN e.start_day AND e.end_day
    ) x
    WHERE e.id = %(event)s
    GROUP BY x.shipment_id
),
target AS (
    SELECT s.id AS sid, s.eta_day, p.id AS pid, p.due_day, p.due_date, p.penalty_per_day, c.city
    FROM customer c
    JOIN orders o ON o.customer_id = c.id
    JOIN promise p ON p.order_id = o.id AND p.status = 'active'
    JOIN fulfilled_by fb ON fb.order_id = o.id
    JOIN shipment s ON s.id = fb.shipment_id
    WHERE c.name = %(customer)s
),
walk (port, sid, delay, path, bufs, delays) AS (
    SELECT port, sid, d0, ARRAY[sid], ARRAY[]::int[], ARRAY[d0] FROM hit
    UNION ALL
    SELECT w.port, f.dst, GREATEST(w.delay - f.buffer_days, 0), w.path || f.dst, w.bufs || f.buffer_days,
           w.delays || GREATEST(w.delay - f.buffer_days, 0)
    FROM walk w JOIN feeds f ON f.src = w.sid
    WHERE cardinality(w.path) <= %(depth)s
),
pick AS (
    SELECT w.*, t.pid, t.due_date, t.penalty_per_day, t.city, t.eta_day + w.delay - t.due_day AS late
    FROM walk w JOIN target t ON t.sid = w.sid
    WHERE w.delay > 0 AND t.eta_day + w.delay > t.due_day
    ORDER BY late DESC, t.pid COLLATE "C" ASC, w.delay DESC, cardinality(w.path) ASC,
             array_to_string(w.path, '>') || '>' COLLATE "C" ASC
    LIMIT 1
)
SELECT u.i - 1, u.sid, s.description, fh.name, pick.delays[u.i],
       CASE WHEN u.i = 1 THEN NULL ELSE pick.bufs[u.i - 1] END,
       pick.pid, pick.city, pick.due_date, pick.late, pick.late * pick.penalty_per_day, pick.port
FROM pick
CROSS JOIN LATERAL unnest(pick.path) WITH ORDINALITY AS u(sid, i)
JOIN shipment s ON s.id = u.sid
JOIN leg lg ON lg.shipment_id = u.sid AND lg.seq = 1
JOIN hub fh ON fh.id = lg.from_hub
ORDER BY u.i
```

## M1. Memory recall (episodic)

Past runs about disruptions at the same hub, one lane away, or of the same kind, with the approved plan and its outcome. The Sentinel posts it; it is shown on every run.

```cypher
MATCH (e:Event {id: $event})-[:AFFECTS]->(h:Hub)
OPTIONAL MATCH (h)-[:LANE]-(n:Hub)
WITH e, collect(DISTINCT h.id) AS hubs, collect(DISTINCT n.id) AS nbrs
MATCH (past:Event)<-[:ABOUT]-(r:Run)<-[:PART_OF]-(d:Decision {kind: 'plan'})
WHERE past.id <> e.id AND d.status = 'approved'
MATCH (past)-[:AFFECTS]->(ph:Hub)
WITH e, hubs, nbrs, past, r, d, collect(ph.id) AS phubs
WITH past, r, d,
     CASE WHEN any(x IN phubs WHERE x IN hubs) THEN 'same hub'
          WHEN any(x IN phubs WHERE x IN nbrs) THEN 'one lane away from ' + hubs[0]
          WHEN past.type = e.type THEN 'same kind of disruption' END AS why,
     CASE WHEN any(x IN phubs WHERE x IN hubs) THEN 0
          WHEN any(x IN phubs WHERE x IN nbrs) THEN 1 ELSE 2 END AS rank
WHERE why IS NOT NULL
OPTIONAL MATCH (d)-[:RESULTED_IN]->(o:Outcome)
RETURN r.id, past.id, past.name, past.start_day, why, d.summary, o.summary, o.cost_usd, o.saved_usd, o.worked
ORDER BY rank, past.start_day DESC
```

## M2. Playbooks (procedural)

Learned rules with use and success counts. Finance reads them: a playbook that failed before (air-freighting full containers) rules that option out today.

```cypher
MATCH (e:Event {id: $event})
MATCH (p:Playbook) WHERE p.event_type = e.type OR p.event_type = 'any'
RETURN p.id, p.trigger, p.action, p.uses, p.successes ORDER BY p.uses DESC
```

## Memory writes (shared state and handoffs)

Every agent writes through `backend/promisegraph/memory.py`:

* `create_run`: `(:Person)-[:REQUESTED]->(:Run)-[:ABOUT]->(:Event)`
* `add_decision`: `(:Agent)-[:MADE]->(:Decision)-[:PART_OF]->(:Run)`, chained `(:Decision)-[:NEXT]->(:Decision)`,
  with `(:Decision)-[:EVIDENCE]->(Event|Hub|Shipment|Promise|Run)`
* `write_clusters`: `(:Decision)-[:FOUND]->(:Cluster)-[:ROOT]->(:Shipment)`
* `write_route_options`: `(:Decision)-[:PROPOSES]->(:RouteOption)-[:FOR]->(:Shipment)`, `(:RouteOption)-[:VIA]->(:Hub)`
* `choose_options`: `(:Decision)-[:CHOOSES]->(:RouteOption)`
* `set_decision_status`: `(:Decision)-[:APPROVED_BY|REJECTED_BY]->(:Person)`
* `record_outcome`, `upsert_playbook`: `(:Decision)-[:RESULTED_IN]->(:Outcome)`, `(:Decision)-[:FOLLOWED]->(:Playbook)`

The next agent reads the previous agent's output from these nodes (for example the Rerouter reads
`(:Decision {kind:'impact'})-[:FOUND]->(:Cluster)-[:ROOT]->(:Shipment)`), never from Python variables.
